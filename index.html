01 How I work

Both sides of the market

Supply and demand are one system. I've worked across listing creation and management, inventory categories, calendars and availability, search and ranking, quote, and checkout. Features rarely stay on one side of that line for long.

The protection layer

Peer-to-peer rental only works if both parties are covered, and correctness there is not optional. This is where most of my depth is: coverage selection and versioning, standalone benefits, additional drivers, claims, and the pricing rules underneath them.

Design before code

Most of my recent work started as a discovery doc: vendor evaluation, data modeling, sequence diagrams, and a written technical design reviewed across teams before a single card was cut.

Measured and tested

Features ship instrumented, so we can tell whether they worked, and tested on the flows that move money: Mixpanel events, RSpec, Cypress, release checklists, staged rollouts, and post-launch monitoring.

Agents in the loop

I build deterministic, LLM-driven tooling around Claude Code to automate parts of my own workflow. The main one turns a card into a pull request that is ready for human review: the change gets written, put through several independent AI review passes, and run against an extensive end-to-end regression suite in Jenkins before anyone opens it. A person still approves and merges. The goal is not to remove the reviewer; it is to make sure that by the time work reaches them, the obvious problems are already gone.
